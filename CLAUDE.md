## 发版前改一下版本号

[`utils/buildInfo.ts`](./utils/buildInfo.ts) 里的 `APP_VERSION`（形如 `v3.0 (Ambient Presence)`）是手工维护的，**做完一轮大功能或者性能优化就改一下**。若只是小修复则不用提起。

它有两个用处：设置页底部显示的就是它；统计还拿版本号那半截当标签，面板按它切分数据。不改的话新旧版本的数字堆在同一个标签下，「这次优化有没有让首屏变快」「新版铺开多少了」就都答不出来。括号里的代号只在界面上显示，不进标签。构建 hash（`BUILD_LABEL`）是自动生成的，不用管。

## Two categories of Chinese text

1. **UI TEXT** — labels, titles, placeholders, alt/aria-label, toasts, settings copy. Translate freely once a file's batch comes up. Confirmed the large majority of `components/` (152 files / ~8055 CJK lines) and `apps/*.tsx` (76 files / ~11011 CJK lines) is this category, but **every file in these folders still needs a pass for embedded protocol literals** (see below) — this app renders protocol-adjacent content (card summaries, quoted-message previews, tag-stripped display strings) inline inside otherwise-ordinary UI components, it's not cleanly separated like a naive split would assume.

   **Sub-case, standing rule (user decision, 2026-09-01, mirrors a prior-project precedent): a label that's injected into an AI-facing prompt/context block as informational text — but never parsed/matched back out of AI output — is safe to translate, not protected.** Example: `utils/memoryPalace/types.ts`'s `PLATE_TITLES` (门牌标题) is a single-source `Record<PlateRoom,string>` used both as a plain UI label (`RoomPlatePanel.tsx`, `MemoryPalaceApp.tsx`, dev `console.log`s) **and** as a section header in `formatRoomPlatesSection`'s output, which gets injected into the character's context (function name literally says "注入格式" = injection format). No regex/`.includes()`/`===` anywhere matches against these Chinese strings — the AI never has to echo them back — so translating just changes what section-header wording the AI reads as context, the same category of "flag it, no technical risk" as the prior project's `notifyMascotPageContext({ label })` case (see the standing rule further below). **This is a different risk tier than OBSERVE's `label` field** (which WAS parsed back — genuinely protected) or the bracket/tag protocols (also parsed back). When evaluating a new file: "does this string get matched/parsed back out of LLM output" is the real dividing line, not merely "does this string get sent to an LLM at all."

2. **AI PROMPT / PROTOCOL TEXT** — do **NOT** touch without asking first. Confirmed protocol shapes found so far (this app has *more* distinct tag systems than the prior similar project, not fewer — do not assume prior project's shapes apply here):
   - **Bracket/XML-style wire-format tags taught to the LLM and parsed back**, found in `utils/chatParser.ts` (consumer) paired with `utils/chatPrompts.ts` and friends (producer):
     - `[[MUSIC_ACTION:add|...]]` — music action tag.
     - `[引用:...]` / `\[(?:QU[OA]TE|引用)[：:]...\]` — quote tag, **bilingual**: accepts both `QUOTE`/`QUATE` (English) and `引用` (Chinese) as the tag keyword. Also a "X引用了Y「quoted text」" variant using `「」` corner brackets.
     - `[回复"..."]` — reply tag using Chinese `回复` + curly/corner quote chars.
     - `<语音>...</语音>` and `<字幕>...</字幕>` — **the tag names themselves are Chinese words** (语音 = voice, 字幕 = subtitle), not just Chinese content inside English tags. Translating the words "语音"/"字幕" anywhere near this system risks breaking the regex that matches the literal tag name.
     - `[Transfer]`, `[协同文件：...]`, `[系统: ... 新增了日程 "..."]` — transfer/collab-file/schedule system-notice tags, mixed English/Chinese.
   - **`⟦OBSERVE⟧...⟦/OBSERVE⟧` block protocol** — **RESOLVED (2026-09-01)**: wire-format field names renamed 时间/地点/状态/细节 → `time`/`location`/`status`/`detail` in `utils/datePrompts.ts`'s `OBSERVE_DIMENSIONS`, doc updated, tests updated, build+tests pass. See Progress log for full detail. `docs/date-observe.md`, `components/date/ObserveHUD.tsx`, `components/date/ObserveSettings.tsx` confirmed to have no separate hardcoded copy of the label (single source of truth via `dim.label`).
   - **`<续>`/`<标题>`/`<主题>`/`<起笔>`/`<动态>` tags** (legacy-compat `<续句>`/`<第一句>`) in `utils/vrWorld/prompts.ts`'s `parseSignalOutput` (docs/signal-poetry.md) — another Chinese-tag-name wire format, cross-user "relay poem" feature, backend counterpart in `worker/post-office/src/index.ts`. Not yet individually read/confirmed.
   - **Memory summarization prompts — CONFIRMED (2026-09-01)**: `utils/memoryPalace/pipeline.ts` and `digestion.ts` read in full, both PARTIALLY protected. See Progress log for exact line ranges of the protected subset vs. confirmed-safe UI/dev-log text.
   - **CONFIRMED PROTECTED, entire file (2026-09-01, read in full)**: `utils/songPrompts.ts`, `utils/lifeSimPrompts.ts`, `utils/guidebookPrompts.ts`, `utils/htmlPrompt.ts`, `utils/thinkingChainPrompt.ts`. New tag instance found: `songPrompts.ts:401` rejects LLM output lines starting with literal `json|歌词|示范|建议|解释|原因|说明` + colon (self-contained producer+consumer, same file).
   - `chatPrompts.ts` (659 CJK lines), `datePrompts.ts`'s non-OBSERVE parts (writing-style preset blocks etc.), `promptMessageCleanup.ts`, `applyAssistantPostProcessing.ts` (581 CJK lines — likely output post-processing, i.e. also consumer-side), `sanitize.ts` (274), plus per-feature `utils/groupChat/prompts.ts`, `utils/like520/prompts.ts`, `utils/vrWorld/prompts.ts`, `utils/worldHome/prompts.ts` — **still not yet individually read/confirmed**, treat as protected until read.
   - `utils/personaSimParser.ts` — **CONFIRMED CLEAN (2026-09-01)**: zero Chinese content, no action needed, can be dropped from the watch list.
   - `utils/videoParser.ts` — **CONFIRMED PARTIALLY protected (2026-09-01)**: line 124's `d.type === '图片'` matches a third-party API's (apizero) own response field — different risk category (external API contract), still do-not-touch. `ERROR_MESSAGES` (67-74) and inline `throw new Error(...)` user-facing strings are safe to translate normally.
   - `utils/chatParser.ts` — parser/consumer-side file by name, not yet individually confirmed (distinct from the already-read files above).
   - **NEW, found 2026-09-01 while translating `constants.tsx`'s app names**: `utils/messageFormat.ts`, `features/collaboration/makers.ts` (specifically the fake phone-mockup HTML template at `makers.ts:421`, sent as an LLM design brief), `utils/qixiMemoryBundle.ts`, `utils/qixiReunion.ts` — all embed app-name-like strings directly into LLM-bound message/prompt content. Not yet individually read in full; treat as protected until confirmed. Also `apps/PersonaSim.tsx:1274-1277` — a JSON app-list scaffold embedded in an AI prompt, protected even though the rest of that file isn't necessarily.

   **Rule of thumb (same as prior project, still holds here)**: if a Chinese string is wrapped in a bracket/angle-bracket tag, assigned to a `content:`-like field of a message/session object, passed to a message-adding function, or matched/compared against LLM output or message content — leave it and report it. Static UI labels for the same feature (buttons/menus/settings copy) are usually safe, **except** where the label is proven to double as protocol data (see OBSERVE case above) — check before assuming.

- **This CLAUDE.md file itself and other `.md` docs**: dev documentation, `.md` not `.tsx`, out of scope for the UI pass per the original instruction — not touching unless asked.
- **`trackEvent(...)` analytics calls — RESOLVED, new cross-cutting rule (2026-09-01)**. Discovered via `docs/analytics.md`: this repo's own written rule for adding tracking events (`## 加新埋点的规矩`, rule 1) says event names are **deliberately** written in Chinese so they match what the user sees on screen ("事件名用中文，跟用户在界面上看到的说法一致——按 F12 的人不用再对照一份英文 slug 表"). 710 `trackEvent(...)` call sites found across 77 files in `components/`+`apps/` (roughly a third of all files in scope). Backend is a self-hosted umami instance (`stats.friedsully.com`) that buckets historical data by the exact event-name string.
  - **User decision: translate `trackEvent` event names and property keys/enum-value literals in lockstep with the UI text they describe, accepting that this permanently splits analytics continuity for any renamed event** (old Chinese-named data and new English-named data become separate series in the dashboard — a one-way, non-reversible cost on the data side, distinct from anything in our own repo).
  - **How to apply**: when translating a UI label/button/toast, if the same file has a `trackEvent('<matching Chinese phrase>', ...)` call describing that action, translate the event-name string to match the new English UI wording (not necessarily a literal word-for-word translation — match the *sense*, like the Chinese original does with its own UI). Do the same for property keys (e.g. `错误类型` → `Error Type`, `所在App` → `App`) and for literal Chinese enum *values* assigned to those properties (e.g. `'没配'` → `'Not configured'`) — but leave English enum tokens alone (`'webdav'`, `'github'`, etc. are already provider ids, not translatable). **Do not touch runtime-derived values** passed into `trackEvent` (anything not a literal string in the source — the doc's own rule 4 already forbids passing runtime strings like `error.message`, so anything already runtime-derived was never a literal to begin with).
  - **Consistency requirement**: reuse the same English wording for the same Chinese concept every time it recurs (e.g. every `打开X` "opened app X" event, every `错误类型` property) — add new event-name/property-key translations to the Glossary section below as they're coined, and check the Glossary first before inventing a new rendering. This matters more here than for ordinary UI text because analytics dashboards group by exact string match.
  - **Structural shortcut worth knowing**: the `打开X`-family "opened an app" events (~30 of them, one per installed app) are generated from **one central place** — `context/OSContext.tsx` interpolates the app's display name from the single app list in `constants.tsx`, per `docs/analytics.md`'s "打开某个 App" section. Translating that one app-name list should be verified to automatically retranslate all ~30 of those events, rather than needing 30 separate manual edits — confirm this by reading `context/OSContext.tsx`'s event-firing code before assuming.
  - `docs/analytics.md` itself is out of scope (a `.md` doc, per the bullet above) — not translating its prose, but its "完整事件清单" (full event list, lines ~276-1181 at time of writing) is the authoritative list of every Chinese event name currently in the codebase and is useful as a cross-reference/checklist while translating, even though the doc file itself won't be edited.
